From AI Pilots To A Managed AI Platform

Executive case

Rahul Dave (Univ.Ai)

A practical case for moving from scattered AI experiments to The Shared Platform that Point32Health can manage, reuse, and improve.

The choice is whether AI work grows in many separate corners, or through The Shared Platform: one managed path that leaders can see, trust, and scale.

BBVA Faced Hidden AI Demand In A Regulated Business

Regulated enterprise

BBVA was not an obvious fast mover: a global bank with heavy regulation, deep compliance requirements, and a large workforce. Leaders saw that employees were going to use AI, so unmanaged use became the risk to solve.

25Countries in BBVA’s global operations.
77M+Clients, which made privacy and trust central.
125kWorkers, enough for hidden AI use to spread quickly.
RegulatedRisk, legal, compliance, privacy, and audit all mattered.
Hidden demandEmployees already had reasons to use AI; leadership needed a managed path.

The setup is the tension: moving slowly leaves AI use unmanaged, but moving fast without controls creates risk.

Source: Garicano et al. BBVA case excerpt supplied by Rahul.

BBVA Made Adoption Social And Useful

Managed adoption

BBVA treated adoption as a change program, not only a software rollout. Early access went to motivated employees, peer support spread know-how, and useful internal assistants became a source of status.

What changed

AI moved from scattered interest to visible participation. People had a reason to use it, share what worked, and help others learn.

Motivated first usersEarly access went to committed employees, not only the most senior people.
Peer networkRegional champions and power users helped people learn from colleagues.
Status and sharingPeople were rewarded for building and sharing useful assistants, not just trying the tool.
Strong implementerElena Alfaro brought bank knowledge, technology judgment, communication skill, and leadership backing.

Source: Garicano et al. BBVA case excerpt supplied by Rahul.

BBVA Then Proved Scale With Control

Measured result

The payoff came after the operating choices were in place: approved access, fast review, prompt privacy, human ownership, quality checks, and visible measurement.

2 mo.Risk, legal, and compliance review moved quickly enough to become the managed path.
83%OpenAI reported weekly active use among early licensed users in 2025.
3 hrsOpenAI reported average time saved per employee each week.

Point32Health needs the same arc, tuned for healthcare: start with visible demand, build the managed path, then scale only with privacy, compliance, evidence, and human accountability.

The Shared Path

The ask

Approve a staged program that creates The Shared Platform for AI agents, shows it works through safe first demos, and gives executives a way to manage the AI portfolio.

Core build team

Product, engineering, security, data, compliance, design, and business experts working as one program.

Shared platform services

Catalog, profiles, agent harnesses, runtime services, evidence, quality checks, and release gates. Human-in-the-loop review is part of the runtime: The Shared Platform routes work to people when review is required.

First demonstrations

Agent harnesses for Codex and Claude Code; DAIS, the legal redlining app, as the first app port; Synthetic Benefits with synthetic data in the same early wave.

The decision today is not a final production launch. The decision is whether Point32Health builds The Shared Platform needed before many teams scale AI agents.

Agent Harnesses Create The First Platform Foundation

Foundation build

The first build creates controlled Codex and Claude Code workspaces, then uses their work to grow the catalog, context indexes, memory, and trace indexes.

1. Agent harnessesCodex and Claude Code launch with approved instructions, allowed files and tools, and named reviewers.
2. Runtime reviewStart with markdown plan/spec review: the runtime routes the plan to people so they can approve, question, or change it before agent work continues.
3. Context captureAs agents work, save the documents, code, decisions, and notes they actually used.
4. Catalog indexes and memoryBuild catalog-owned search stores and memory, including vector databases for meaning-based search.
5. Trace indexesIndex the step-by-step traces so reviewers can inspect, compare, reuse, and debug agent work.

The benefit is that DAIS, Synthetic Benefits, and later teams inherit these platform functions instead of rebuilding them: harnesses, human review, context capture, catalog memory, and trace indexing.

Applications Are The Next Step

First applications

After the agent harnesses, the next step is to test The Shared Platform with two applications: DAIS, our legal redlining pilot, and Synthetic Benefits, using synthetic data.

1. Application controlsKeep the harness controls; add app-specific users, tools, screens, and limits for each workflow.
2. Runtime reviewKeep markdown plan/spec review; add DAIS redline review and Synthetic Benefits answer review through the shared runtime.
3. Context captureDAIS adds legal documents and contract language; Synthetic Benefits adds plan documents, benefits rules, and provider data.
4. Catalog indexes and memoryKeep catalog-owned search and memory; add redline examples, benefit examples, reviewer decisions, and reusable patterns.
5. Trace indexesKeep step-by-step traces; add app outcomes such as accepted redlines, changed answers, issues, and time saved.

The application work improves the harness foundation instead of bypassing it.

The Four Platform Parts

Four parts

Every AI effort uses the same four parts: one agreement on what is allowed, one shared view of the work, one controlled place to run it, and one record of what happened.

ProfileThe approved instructions for one AI effort: owner, purpose, data, actions, review, and stage.
CatalogThe shared map of AI work: owners, risks, approvals, value, evidence, and readiness.
RuntimeThe controlled place where approved AI work runs, uses only the access it needs, and routes required human review.
EvidenceThe record of what happened: data used, tools called, approvals, outputs, issues, and results.

A profile says what is allowed. The catalog shows the portfolio. The runtime runs approved work safely, including required human review. Evidence shows what happened and why decisions were made.

The Catalog Shows What Context An Agent May Use

Catalog and context

Context means the information given to an agent for one task. The catalog shows which sources are approved, who owns them, what limits apply, and what must be saved as evidence.

RequestWhat the person is asking the agent to do, and what outcome is expected.
Approved sourcesPolicies, plan rules, workflows, examples, and operating guidance cleared for this kind of task.
Allowed dataOnly the records, documents, and data packages the task is allowed to use.
Runtime limitsWhat the agent may do with the context, and when a human must review it.
Source recordWhere the information came from, which version was used, and why it was allowed.

Every Agent Run Starts With A Check

Runtime

A run is one piece of AI work. Before it starts, the runtime checks the profile, owner, purpose, data, allowed action, review need, and release stage.

Check the profileConfirm owner, purpose, limits, and stage.
Check accessGive only the narrow access needed for this task.
Check approved dataUse approved sources and versions, not unapproved places.
Run the workCall the model, tools, and shared human review steps through the runtime.
Write evidenceRecord decisions, data used, tool calls, approvals, results, and issues.

This is how speed stays safe: each run gets narrow access for that task instead of ongoing broad access.

The Evidence Layers

Evidence layers

Evidence is not one log file. It is a set of records that gives control teams the facts they need.

Decision recordWho approved the work, what profile applied, and what stage it was allowed to run in.
Context recordWhich information was provided to the agent, from which source, and under which limits.
Run traceWhat the agent did step by step: model calls, tool calls, outputs, and errors.
Review recordWho reviewed the output, what they changed, and whether it was accepted or rejected.
Outcome recordWhether the work saved time, improved quality, reduced risk, or created follow-up work.

Every Important Run Leaves Evidence

Auditability

What was approved?The profile, owner, and allowed stage.
Who got access?The exact data, tool, system, and time limit.
What was used?Approved data source, version, citation, and context.
What happened?Model calls, tool calls, human review, output, and exceptions.
What was decided?Approval, failure, move-forward gate, rollback, or improvement item.

Evidence protects the company and helps teams improve. It gives Security and Compliance the record needed for audit, quality review, incident response, and future reuse.

Access Is Decided, Limited, And Recorded For Each Run

Security and access

For each run, the platform asks who is requesting access, why it is needed, what data or tool is required, and what human review applies.

Decision per run

Approve, deny, narrow, or require human review for that task.

Short lived

Access expires and can be revoked.

Purpose bound

Access is tied to the approved task, stage, and business purpose.

Recorded

The decision, exchange, and next step are saved as evidence.

Because the decision is recorded, Security and Compliance can see why access was granted, narrowed, denied, or sent for review.

Audits For Compliance And Security

Audit tests

Because runs leave evidence, AI can help test the work itself. Security and Compliance can scan traces, context, citations, outputs, and reviewer decisions for known problems.

PHI checks

Look for sensitive data that was not needed, missing masking, wrong retention, or use outside the approved purpose.

Prompt exfiltration

Test whether prompts or outside content can trick the agent into leaking data, ignoring rules, or calling the wrong tool.

Fairness checks

Review outputs for unfair treatment, unsupported denials, missing citations, or inconsistent decisions across similar cases.

Exception checks

Find unresolved exceptions, failed tests, reviewer overrides, incidents, and release blockers before the work expands.

This makes evidence useful, not passive: AI helps inspect the record, and humans decide what must be fixed before release.

Healthcare Risks Are Built Into The Platform

Healthcare guardrails

Minimum necessary data

Use only the data needed for the approved task, with the approved masking rules.

Unsafe content and tool use

Treat outside content carefully, control tool use, and test for data leaks or manipulation.

Human review

Clinical, financial, denial-related, external, or system-changing actions require the right human approval.

Risk Platform response
Too much sensitive data Clear data rules, use only what is needed, masking, and retention rules.
Unauthorized action Approved tools, access checks, narrow access, and approval gates.
Unsafe release Quality tests, security review, compliance signoff, monitoring, and rollback.

Controlled growth

Release gates are checkpoints before an AI effort expands. Each gate asks whether the owner is clear, the data is approved, the human review is working, the controls are working, and there is a rollback plan.

prototype

production

AI Will Change, But The Rules Stay Clear

Future readiness

Delegated work

If one agent asks another agent for help, that added work still needs limits, budget, owner, and evidence.

Memory

Only approved past work should become reusable memory, and it must keep owner, privacy, and source links.

Improvement

Prompts and workflows should improve against approved examples and quality checks, not hidden experiments.

Summaries

Short summaries should link back to the original source and carry warnings when they are incomplete.

New platforms

Azure, Databricks, OpenAI, and future tools can change while the business rules stay consistent.

Feedback

Human feedback should become quality evidence, not disappear after the meeting or chat.

Trusted Enterprise Systems Can Carry The Platform

Enterprise systems

The technology direction is to keep AI work inside trusted enterprise systems where they fit, and to make exceptions visible.

Azure for enterprise control

Identity, app hosting, API management, monitoring, search, model oversight, and secrets should use approved enterprise services where they fit.

Databricks where the data lives

Data, analytics, machine learning work, and data rules should stay close to approved enterprise data when that is the right home.

Exceptions are deliberate

Special tools can be added when they solve a real gap, but they should not become hidden places where important decisions happen.

The architecture goal is simple: one visible set of rules, even when the tools underneath differ.
